# multi-agent-driven

把当前任务变成一次有编排的多智能体执行。你始终是编排者：拆解、派发、整合。不要自己做子任务，也不要把一个上下文装得下的活硬拆出去。

**语言**：跟随用户的语言。

## 步骤

1. **给任务分类，选对应模式**：
   - 调研 / 排查 → 不同角度的并行 explorer（按来源、按子系统、按时间窗），最后综合
   - 多处实现 → 先摸清完整工作清单，再一处一个 agent 流水线推进；agent 会并行改同一个仓库时用 worktree 隔离
   - review / 审计 → 按维度并行找问题，每个发现再配一个对抗式验证者
   - 设计决策 → 2–3 个不同侧重的独立方案 agent（MVP 优先、风险优先、用户优先），再加一轮评审
   - debug → 并行假设检验者，每人负责证伪一个假设
2. **spawn prompt 写成任务契约**（handoff 纪律）：目标、按引用给的输入（路径 / issue / URL，不粘贴正文）、边界（不许碰什么）、期望的输出形状。
3. **派发**：互相独立的 agent 并行出发；有依赖的阶段做流水线，不设人为的等待关卡。优先用平台原生的编排（Claude Code 用 Agent 工具或 Workflow；其他平台就顺序调 subagent）。
4. **整合**：自己读结果、自己裁决 agent 之间的冲突、验证合并后的结论（重跑测试、抽查断言），汇报一个整合过的结论，不是一堆 agent 输出的堆叠。

## 规则

- 实质性的 subagent 工作默认用最强档位模型（opus-high / sonnet-max / xhigh 一类）；只有琐碎的机械阶段才降档。派发时显式写明档位。
- 拆解跟着上下文耦合度走：需要彼此中间上下文的子任务留在一个 agent 里；只有真正独立的切片才分出去。拿不准就少拆。
- 每次派发都写明覆盖范围：包含了什么、丢掉了什么。不许静默截断。
- subagent 的结果是主张，不是事实。整合前先验证：重跑测试、重开文件、重查引文。
- 依赖方向单向：本 skill 可以用 `handoff`；永不调用面向用户的 skill。
