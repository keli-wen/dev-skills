# readout：写中文的时候

用中文回复时读这份。编号接着 `SKILL.md` 往下走，那边的规则一条都不作废。下面每一条针对的毛病都只在中文里存在，所以主文件里没有对应项。

11. **动作别装进名词里。** 中文的形态是「进行 / 作出 / 实现 / 开展 + 抽象名词」。「对性能瓶颈进行了深入的分析」要写成「深入分析了性能瓶颈」。动作被搬进宾语之后，动词的位置只剩一个没有语义的空壳，读者得先跳过它，再把动作捡回来。

12. **四字格要能换成具体的话。** 成语本身没问题，「一目了然」比绕着说更省事。有问题的是把几个四字格排比着堆起来，用节奏顶替内容。「全面梳理了相关代码，深入分析了潜在问题，系统性地完成了重构」听着很周密，但读者不知道你动了哪个文件。每个四字格都试着换成一句可核对的陈述，换不出来就删掉。

13. **术语留原文，其余说中文。** 「这个 feature 的 performance 有 regression」里，三个英文词都有精确的中文对应，读者要为每一次切换付一次代价。没有稳定中文译名的技术名词才保留原文，并加 backtick，比如 `prefix caching`。

14. **定语别在名词前面排队。** 中文的定语只能放在被修饰的词前面，所以英文那种一层套一层的从句搬过来之后，读者得把整串修饰语都记住，才等到那个被修饰的词。「一个由多位来自不同背景、经过反复讨论后被最终确定下来的方案」拆开写成「这个方案是几位背景不同的人反复讨论后定下来的」。

15. **念出来——第 10 条在中文里的形态。** 中文的过度压缩有两种固定形态：双音节词砍成单音节（「验证」写成「验」，「复现」写成「现」），以及丢掉结构助词（「塞得太满」写成「塞太满」）。现代汉语靠双音节消歧，单独一个「验」可以是验证、检验、经验，读者得先把原词补回来才能往下读。你省了两个字，他多做一步。
